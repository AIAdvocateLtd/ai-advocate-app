# RCA — Lex AI chat replies blank / cut off (ai-law-guide-1)

Read-only production investigation. No prod data/secrets/config changed. No message
bodies (user_message / assistant_response) were read or decrypted.

## Summary
The deployed backend contains the SAME buggy `lex_model_for_tier()` seen in preview: it
routes Free / Pro / Deep Think to Anthropic `claude-*-5-5` models which (per the preview
finding) burn the entire output budget on hidden reasoning tokens, so the visible reply is
empty. The buggy version went live ~2026-11-03 and is the current active run.

## 4. Backend logs
Tooling caps log lookback at 24h (not the requested 14 days). Checked the active run
(2f1ec1d6, up since 2026-11-04T01:10) and the first `-5-5` run (40d30976): **0 matches** for
"Primary model", "falling back", "Streaming completion failed", Anthropic/LiteLLM errors,
`claude-*-5-5`, "reasoning", ERROR, WARNING, or Traceback. Sampled traffic is all **200 OK**
(status histogram 100% 200), including `POST /api/lex/taster` 200. This is consistent with
the blank-reply failure mode: the model returns `finish_reason=length` with content empty,
the handler returns HTTP 200 with an empty body, and no exception is logged.
Caveat: the full 14-day window could not be read; absence of errors in 24h is not proof none
occurred earlier.

## Root cause
Deployed `lex_model_for_tier()` routes Free/Pro/Deep-Think to `claude-haiku-5-5` /
`claude-sonnet-5-5`, which (confirmed in preview) exhaust the `max_tokens` budget on hidden
reasoning tokens → empty/truncated visible replies. Confirmed the buggy code is live and when
it shipped. Metadata corroborates: `-5-5` adoption is near-zero in both `llm_usage` (0 rows)
and `conversations` (2 rows) since the switch, while no recorded output is blank — consistent
with the new path failing to produce usable replies.

## Not reproduced in sandbox
The eph pod has no `EMERGENT_LLM_KEY` / Anthropic credentials, so the blank-reply behaviour
itself could not be re-run in-sandbox. What IS proven from prod: the exact deployed model
routing + max_tokens, deploy timing, and the metadata pattern. The "reasoning eats the budget"
mechanism is carried over from the preview finding, not re-observed here.

## Suggested fix (Code — E1)
In `backend/server.py::lex_model_for_tier()`, stop routing to the `-5-5` Anthropic models as
configured. Options: (a) revert to the working ids (`claude-sonnet-4-5-20250929`,
`claude-haiku-4-5-20251001`), or (b) if `-5-5` must stay, disable extended-thinking / set an
explicit reasoning budget and raise `max_tokens` so visible output tokens remain. GPT-5.2
(Plus) is unaffected and can stay. Redeploy after the code change. Also worth adding a guard
that logs/raises when `finish_reason=="length"` with empty content so this fails loudly next
time.
