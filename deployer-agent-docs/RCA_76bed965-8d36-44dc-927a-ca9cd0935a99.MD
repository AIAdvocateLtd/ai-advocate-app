# RCA — ai-law-guide-1 redeploy failed at deploy_k8s (cluster infrastructure)

## Summary
Two consecutive redeploy runs failed at the **deploy_k8s** step with `deployment failed to become ready: timeout waiting for deployment to be ready`. Root cause is **cluster/network infrastructure on target-8**, NOT the app source or deployment manifests. The live app is unaffected — the previous successful run remains active and serving.

## Affected runs
- `853a5665-6df3-4087-82a9-5a166ceeda28` (initial reported failure)
- `76bed965-8d36-44dc-927a-ca9cd0935a99` (my retry — same failure)
- Cluster: `target-8`, namespace `customers-app`
- Template: `fastapi_react_mongo_shadcn_base_image`, tier_1, amd64

## Evidence
From `get_pod_events` on both runs:
- **Cilium CNI down / rate-limited** (pod networking cannot be provisioned):
  - `FailedCreatePodSandBox ... plugin type="cilium-cni" failed (add): agent is down: failed to create cilium agent client after 30s timeout: Get "http://localhost/v1/config": context deadline exceeded`
  - `... failed (add): unable to create endpoint: [PUT /endpoint/{id}][429] putEndpointIdTooManyRequests`
  - `... unable to create endpoint: Cilium API client timeout exceeded`
- **Node-pool saturation / pressure**:
  - `FailedScheduling ... 0/157 nodes are available: ... 141 Too many pods, 12 Insufficient cpu, 2 Insufficient memory`
  - `Evicted: The node was low on resource: memory`
- **App image is healthy**: image pulled successfully; a replica started and logged `Starting FastAPI backend: uvicorn server:app --host 0.0.0.0 --port 8001 --workers 1 in /app/backend`. The pod simply never reached Ready before the rollout timeout because sandbox networking repeatedly failed.

## What is NOT the cause
- Not source code: same image family and prior redeploys (5b6a373c, fa211346, 3a96e343) all succeeded; backend booted this time too.
- Not manifests: no Dockerfile/entrypoint/nginx change involved; failure is at K8s scheduling/CNI, before app readiness.
- Not secrets/DB: backend process reached startup.

## Impact
None to end users. A failed run is never promoted; active run `5b6a373c-5d6f-4142-832d-f1afc10c3496` continues serving `https://ai-law-guide-1.emergent.host` (and custom domains aiadvocate.co.uk / www.aiadvocate.co.uk).

## Remediation (Platform)
- Investigate Cilium CNI agent health and endpoint API rate-limiting (429s) on `target-8`.
- Address node-pool capacity pressure (Too many pods / Insufficient cpu / memory / evictions) — likely needs scale-up or rebalancing / a different target cluster.
- Once cluster health is restored, re-trigger the redeploy. No source or manifest change is required.

## Retries already spent
One authorized infra retry was performed (run 76bed965) and hit the identical failure. Further re-fires without platform remediation will fail the same way.
