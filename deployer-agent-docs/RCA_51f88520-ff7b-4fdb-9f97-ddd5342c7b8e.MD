## Root cause
Account deletion (`DELETE /api/users/me`) purges child-collection docs correctly, but the final `users`-doc anonymisation is incomplete: `email`, `full_name`, and `country` are left as original PII, and the password hash survives because the code nulls `hashed_password` while the stored field is `password_hash`.

## Suggested fixes
- **Code (E1):** In the deletion anonymiser, also overwrite `email` → `deleted-<id>@ai-advocate.local`, clear `full_name`, clear `country`, and null the correct field `password_hash` (reconcile the `hashed_password` vs `password_hash` field-name mismatch). Backfill the 1 existing residual record. No tool here can write; requires code change + redeploy.
- **User (verify):** No email-send audit record is persisted, so export-email usage cannot be confirmed from the DB; if an audit trail is desired, persist send events to an email-log collection.
