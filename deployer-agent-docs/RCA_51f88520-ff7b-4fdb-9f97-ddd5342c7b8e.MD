## Q2 — Secret LAW_WATCH_WRITE_ENABLED add/remove: redeploy needed? rollback preserved?
- Redeploy required: YES. The production pod's environment is composed and written at the `write_secrets` step of a deploy run and baked into that run's pod env. A secret added or removed in the Deployment Panel does NOT propagate to the running pods until a new deploy run executes. So both adding and later removing LAW_WATCH_WRITE_ENABLED each require a redeploy to take effect in production.
- Previous run preserved for rollback: YES. Each deploy produces its own run with its own built image, and run history is retained (recent history shows multiple prior successful runs with distinct images, e.g. a5d30a90..., fde1ffeb...). Rollback reuses an already-built earlier image, so the prior run remains available to roll back to after a redeploy.
- Caveat: rollback restores the earlier IMAGE + that run's env composition; it does NOT restore database contents. A rollback will not undo data written to the new collections.
