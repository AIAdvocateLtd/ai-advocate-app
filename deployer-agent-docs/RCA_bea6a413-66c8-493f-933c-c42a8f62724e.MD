## 6. Outbound HTTPS from prod backend — host-by-host
Confirmed from backend logs (last 24h, active run) and source (`national_law.py`):
- **www.gesetze-im-internet.de (DE source, `_de()` connector): FAILING at the network level.** Every DE lookup logs `INFO:national_law:national lookup failed DE <law> <art> after ~12.5s: ConnectTimeout('')` — repeated across many provisions (bgb 573/622/623/..., agg, kschg, milog, etc.). ConnectTimeout = TCP/TLS connect never completed (not an HTTP error) → egress to that host is blocked/dropped, not a 4xx/5xx from the site.
- **www.boe.es (ES source, `_es()` connector): SUCCEEDING.** Many `INFO:httpx:HTTP Request: GET https://www.boe.es/datosabiertos/... "HTTP/1.1 200 OK"` in the same window.
- **testphase.rechtsinformationen.bund.de: not referenced anywhere in the backend source** (grep found no usage). The app does not call it, so there is no app-log signal to confirm/deny — cannot verify from this deployment.

Net: outbound to gesetze-im-internet.de is failing with ConnectTimeout while boe.es works from the same pod — a host-specific egress/reachability problem, either a cluster egress block or that host rejecting the datacenter egress IP.
